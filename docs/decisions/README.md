# Architecture decision records

Store decisions separately from task instructions and validation reports. There are no newly approved production architecture decisions in this directory.

Use `NNNN-short-title.md` with: identifier, title, status (proposed/accepted/rejected/superseded), business and technical context, options, selected approach, rationale, consequences, security implications, reversal/migration considerations, and approval evidence/date.

Only mark a decision accepted when the project owner or an authorized decision-maker approves it. A handoff proposal, generated draft, or passing test is not approval. Preserve superseded records and link replacements.

Candidate topics from [handoff Section 22](../context/project-handoff.md): identity, REST/GraphQL, backend modularity, data ownership, logistics, events, payments, MerryGO federation, hosting, and mobile framework. Listing these topics does not select an approach or authorize implementation.
